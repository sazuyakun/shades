# packages/ShadesKit: the Swift modules

All real Mac code lives here as a Swift package with one module per system. The app in `apps/mac` just wires them together. Root rules in `/CLAUDE.md` still apply, **including all Swift conventions** (style, errors, logging, tests).

## Modules
| Module | Owns |
|---|---|
| ShadesCore | Model types: Project, Sequence, Track, Clip, time, IDs. Foundation only |
| ShadesCommands | Command protocol, registry, undo, JSON schemas |
| ShadesDocument | `.shades` package (project, session, snapshots, thumbnail), the `~/Shades` library. Autosave timing lives in ShadesUI's `Workspace` |
| ShadesMedia | Import, audio decoding, thumbnails and filmstrips, proxies, the background `JobQueue` |
| ShadesEngine | AVComposition builder, Metal compositor, playback, shaders |
| ShadesColor | Color management, grade nodes, LUTs, scopes |
| ShadesGraphics | Titles, templates, keyframes |
| ShadesAudio | Speech activity and noise reduction (ported), beat detection, waveforms, loudness (BS.1770), ducking plans, and stem separation (HTDemucs on CoreML, its model downloaded on first use) |
| ShadesCaptions | WhisperKit transcription (models, audio decoding), caption lines. The only module that imports WhisperKit |
| ShadesExport | Exports: canvases (the 4:3 picture centred on 16:9 or 9:16 black), movies through `AVAssetExportSession` with our compositor (the engine draws the canvas), frames, GIFs and SRT captions. The queue is the app's `JobQueue` |
| ShadesMCP | MCP server: commands become Claude tools |
| ShadesMatting | Cut-outs (mattes): Apple Vision finds the subject, written as a small gray video played like any track (each clip refines its edge, `CutoutEdge`, where the engine's `matteFragment` samples it); the subject's path over time for reframing; optical flow for footage motion blur, written the same way |
| ShadesPolish | Polish for talking-head footage: the rule-based planner (silences, fillers, retakes, beat snaps, punch-ins) and `ApplyPolish`. Pure logic on Core and Commands |
| ShadesPlugins | Plugin folders (Settings), loading plugins (`PluginLoader`), and `PluginLibrary`: kept up to date with FSEvents, fonts registered for the app. Data only (on Core); templates are applied by `ApplyTemplate` in Commands |
| ShadesUI | SwiftUI views (AppKit/Metal where SwiftUI is too slow) |

Modules are created only when a milestone first needs them. They exist today: ShadesCore, ShadesAudio, ShadesCaptions, ShadesCommands, ShadesDocument, ShadesMedia, ShadesEngine, ShadesExport, ShadesMatting, ShadesMCP, ShadesPlugins, ShadesPolish, ShadesUI (plus `ShadesTestSupport` for tests). The rest of the table arrives with their milestones.

## Rules
- **Dependencies point one way:** Core → Commands / Document → feature modules → MCP → UI → the app. Core imports only Foundation, nothing imports ShadesUI except the app, and ShadesMCP never imports ShadesUI (UI reads `MCPServer.status` to show Claude's connection).
- **Every edit is a command** (`Codable`: name, description, parameters). Registering it exposes it to menus, shortcuts, undo and Claude. Never add an AI-only shortcut, and never let the UI mutate the model directly.
- **Every user action is an `EditorAction` case** (title, `Shortcut`, `perform(in:)`). The editor window's one `onKeyPress` handler and the ⌘K palette both read that list, so never attach `.keyboardShortcut` to a button for an editor action. Only standard menu items (undo/redo, checkpoint, new/open, export, Settings) live in menus (`FileMenu`).
- **One open project.** `Workspace` (ShadesUI) owns the editor, player and MCP server and opens one project at a time; Claude's project tools reach it through the `ProjectHost` protocol, since ShadesMCP never imports ShadesUI.
- **Saved projects must keep opening.** When a saved model field is renamed or reshaped, its `Codable` reads the old form too, and `ProjectFormatTests` gets a test with the old JSON. New fields decode with a default (`decodeIfPresent`).
- **Claude's History** (`ActivityLog`, saved as `history.json`): every edit tool call is a step of a `ClaudeRequest` holding its `ProjectChange`, and `UndoChanges` takes a whole request back while keeping later edits. A background job that edits the project when it lands must log that edit under the request that queued it: read `server.activity.runningRequestID` when enqueuing, then call `server.activity.record(_:summary:from:to:in:)` after `editor.perform` (see `useStems`).
- The model is plain data. The engine reads it and builds what plays; ShadesUI never touches AVFoundation.
- Shaders ship as `.metal` source and compile at runtime (so Claude can write effects).
- Swift 6 strict concurrency. **ShadesUI** uses main-actor default isolation; every other module is nonisolated by default, with actors for caches and analysis and `@concurrent` for heavy work. Render paths never touch the main thread.
- Each module has one error enum (`<Module>Error`, e.g. `MediaError`) and one `Logger` with category `<Module>` (e.g. `Media`).
- **Background jobs** run on `JobQueue`. Long work calls `JobQueue.pausePoint()` between chunks (frames, segments) so it holds while the Mac is hot, in Low Power Mode or, for everything but exports (`pausesOnBattery: false`), on battery. `Workspace` checks the real Mac (`JobQueue.systemPause`); a bare `JobQueue()` and test workspaces (`pauseCheck: { _ in nil }`) never pause, so tests run the same unplugged.
- Respect the 8 GB RAM budget: bounded caches, texture pools, no CPU copies of frames.
- **Speed** lives in one mapping: `Clip.sourceTime(at:)` and `timelineTime(atSource:)` (built on `SpeedCurve`) turn timeline time into source time and back, using the clip's `speed` (0 is a freeze frame) or its `.speed` keyframes (in source time, like every keyframe). Never compute source times with `sourceStart + duration` or a fixed offset; use `sourceEnd` and the mapping. Speed changes go through `Project.replaceClip`, which keeps the clip's last frame and ripples its track. The engine places media only through `MediaPiece` (one per frame on a ramp), so playback, export and the mix all land on the frames the mapping names.
- **Motion blur** has one setting chain: the timeline's `shutterAngle` (degrees, 180 by default) times the clip's `motionBlur` (1 follows the timeline, 0 is off). Moving layers are drawn at several moments inside the shutter, centred on the frame, and averaged in a half-float buffer; the sample count grows with how far the layer travels. Footage blur (`footageBlur`) reads the media's optical flow: a BGRA video in the footage's stored orientation, red and green holding the motion in pictures per second (0.5 is still). `RenderQuality` caps samples lower for playback (`.preview`) than for export and frames (`.full`).
- **Text** is drawn by Core Text on the CPU into a surface the GPU places (`TextRenderer`, cached in `RenderContext`): words in wrapped lines, or each glyph stood on a path (`TextContent.path`, or the style's `arc`) and turned with it. A per-word layer (`TextContent.word`, made by `split_words`) lays out the whole text and keeps only its word's picture, centred where the word sat. **3D type** (`TextStyle.extrusion`) has no meshes: the text's picture plus its signed distance field (`DistanceField`, made on the CPU across all cores) is drawn as instanced slices stacked through the letters' depth (`solidVertex`/`solidFragment`, at most 96), each slice pulled in by the bevel near the front and lit from above left by normals from the field's slope, turned with the layer, its bend and the camera. Slices stack premultiplied into the kept half-float trail buffer, which is then composited like a motion-blurred layer, so masks, depth slots, blend modes, transitions and motion blur all apply. Chosen over triangulated glyph meshes because it reuses the layer pipeline, needs no tessellation or depth buffer, and costs one small extra texture per title.
- **Preview size:** `Player.previewQuality` (Auto, Full, Half) only changes the render size of the player's copy of the video composition; instructions keep the full `pictureSize`, and `isCanvas` says whether frames are a canvas. A non-canvas frame is drawn at the output's own size, with `scale` passed to the renderer so pixel-sized effects (blur, halation) cover the same part of the picture. Exports and frames for Claude always render full size.
- **Colour:** the working space is SDR Rec.709. Playback and frame compositions set no colour properties, so AVFoundation hands frames over untouched with their own tags (asked for Rec.709, it converts on some Macs and only relabels on others, like the CI runner). `MetalCompositor` opts in to HDR and wide-colour frames, the layer shader converts whatever each frame is tagged with (`SourceColor`: P3 and Rec.2020 gamuts to Rec.709, HLG and PQ tone-mapped), and every output frame is tagged Rec.709. `MovieExporter` adds Rec.709 primaries and matrix to its copy of the composition, because the file's tags come from those properties. Each `Media` keeps its file's tags (`VideoColor`) for the UI badge and Claude.
- **Sound** is mixed by AVFoundation from the timeline: clip and track volumes, fades and the master level are `AVAudioMix` volume ramps (smoothed by AVFoundation over about 25 ms); anything that needs sample accuracy (the master limiter) runs in each track's `TrackTap`, as does pan. A tap gets each clip's sound in its own channel count, so mono sound pans only from its stereo copy (`stereoSound`, made in the background when a track pans it); noise-cleaned sound is written stereo for the same reason. A sound track whose last clip is retimed and reaches the timeline's end (`Composition.runsOn`) runs on for `Composition.runOn` past it with more of their last sound, silenced by the mix, because the pitch-keeping stretcher drops a sped-up clip's last moments under load when its track simply stops (an empty stretch doesn't keep it going); playback stops at the end (`forwardPlaybackEndTime`), exports end there, and `MixReader` returns exactly the timeline. The limiter is the timeline's `limiter` gain envelope, worked out from the mix's `LoudnessProfile` (5 ms slices of K-weighted energy and 4× true peak) by `normalize_loudness`, and dropped when the master level is set by hand.

## Testing
- Swift Testing, with one test target per module (`ShadesCoreTests`, …). Rules are in the root CLAUDE.md.
- **Golden frames:** every effect, layer and grade gets a render test that ends with `#expect(try GoldenFrame.matches(png, named: "<kebab-name>", in: golden))`. References live in a `Golden/` folder next to the test file (excluded from the target in `Package.swift`). A missing reference is recorded and fails once; re-record after an approved visual change with `SHADES_RECORD_GOLDEN=1 swift test …`, and commit the PNGs. A mismatch writes `<name>.actual.png` (git-ignored) to compare.
- **MCP scenarios** (quality gate 2) are scripted Claude sessions over real HTTP through `MCPTestClient` (ShadesTestSupport). Tools that need only the server go in `ShadesMCPTests/MCPScenarioTests`; tools that need the project host (captions, sound, export, plugins, cut-outs, Polish) open the app's real workspace with `ScenarioWorkspace.open(port:plugins:)` in ShadesUITests, which loads plugins only from the folder given. Visual steps end with a golden frame from `render_frame`. Every test server listens on its own fixed port, never shared: suites run in parallel, so grep the tests for `47_4` before picking one.
- Rendered-frame snapshot tests to keep preview and export identical.
- Tests that need a speech model run only with `SHADES_WHISPER=1` (it downloads the Small model once, about 485 MB). Spoken test audio comes from `SpeechFixture` (the Mac's `say`), never real recordings.
- **Performance gates:** budgets live in `PerformanceTests` (one suite per module that has hot paths, `.serialized`), measured with `Benchmark.median` and `Benchmark.memoryFootprint()` from `ShadesTestSupport`. Budgets are set for the CI runner; never loosen one to make a regression pass, fix the regression. Suites are enabled only with `SHADES_PERFORMANCE=1` and run alone: `SHADES_PERFORMANCE=1 swift test --package-path packages/ShadesKit --filter PerformanceTests --no-parallel` (CI does this as its own step). Gated today: frame render time (with and without motion blur), memory growth, export speed (Export), PLAN §4's playback timeline in real time with no dropped frames and scrubbing (50 ms on the M1, 150 ms on CI) with the 1.5 GB ceiling (Engine), opening a 10-minute 4K project under 2 s, an edit reaching the timeline and preview within a frame, idle CPU and memory (UI), and analysis time (Audio). Playback gates attach an `AVPlayerItemVideoOutput` so the player draws frames without a window.
